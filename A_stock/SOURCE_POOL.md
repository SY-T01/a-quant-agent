# 多源轮换与故障切换

更新日期：2026年11月11日。默认自动下载接入三家独立来源：东方财富、腾讯、BaoStock。AKShare是适配工具，不额外算一家来源；不同东方财富域名也不算多源。

## 实际运行顺序

1. 先检查本地缓存。只有证券代码、复权口径、请求区间、末条日期及字段校验符合要求，才复用缓存；缓存命中时不额外联网，也不推进轮换。
2. 需要新下载时，首次从东方财富开始，之后为腾讯、BaoStock。
3. 成功后，将下一次新下载的起点推进到后一家。例如本次腾讯成功，下一次先尝试BaoStock。游标按证券及复权口径持久化，重启不会总回到第一家。
4. 来源返回错误、空数据、价格异常、缺成交额、少于61条或未更新到所需交易日，立即尝试下一家；一次下载每家最多尝试一次。
5. 单家故障只影响该来源。网络或质量失败冷却5分钟起，连续失败可延长至30分钟；明确限流冷却60分钟。已知东方财富原有冷却截止时间仍然遵守，不通过轮换同平台地址绕过。
6. 冷却来源自动跳过，到期后重新参与；成功后清除连续失败计数。不支持的证券市场直接跳过，不把它误判为整家来源故障。
7. 全部来源不合格或都在冷却时，暂停推荐，不消耗DeepSeek，不把旧数据当作最新数据发信。

轮换发生在真实下载之间，不是每30秒检查一次就请求三家。一天有有效缓存时继续复用，可以减少各家被请求的次数。

## 支持范围和数据口径

| 来源 | 当前适配 | 当前验证 |
|---|---|---|
| 东方财富 | AKShare股票和ETF日线，qfq参数 | 原有真实调用成功记录，也观察到限流 |
| 腾讯 | AKShare腾讯历史日线，qfq参数，统一字段和单位 | 159567截至11月10日683条通过校验 |
| BaoStock | 匿名登录、日线、adjustflag=2，独立25秒超时进程 | 159567截至11月10日683条通过校验 |
| 新浪 | 已探测ETF日线，暂不加入本自动池 | 接口没有直接提供同样复权参数，不能将其原始价格冒充前复权数据 |

本轮比较了159567的腾讯和BaoStock数据：末条日期一致，末条价格、20日收益和60日均线一致。这是指定样本的验证，不表示所有证券、日期及公司行动处理永远一致。每次自动下载使用一家完整序列，不拼接不同供应方价格，也不把缺失成交额估算填入。当前不覆盖所有北交所证券或其他特殊基金品种。

股票名称引用缓存与行情价格缓存分开。已核实的准确代码可复用7天名称；名称源异常时可沿用历史名称并标记“名称沿用缓存”，但价格仍须满足最新已完成交易日。未知代码不会被随意命名。

## 状态与日志

运行`./run.sh watch-status`，可查看各家冷却状态及下次新下载的优先来源。本地自动日报目录中的`data/sources.sqlite`记录游标、来源健康状态与每次尝试；`data/sources.lock`避免并发重复下载。失败日志只存异常类型，不存远程响应正文或密钥。

缓存元数据和邮件记录实际来源、是否使用缓存、错误后换源的尝试轨迹。并非每次报告都同时请求三家，也不是每次都做跨源比价。BaoStock SDK在短时子进程运行，超过25秒终止该次查询，避免其内部网络重试长时间卡住。

## 如何使更新生效

在用户原来启动任务的终端按Ctrl+C，再执行：

```sh
./run.sh watch
```

本次修改未另行启动后台任务。仍维持每交易日14:00一次的配置，仍是已完成日线研究，不等同于当日实时行情。免费公开接口的可用性没有保证，任何时候都保留数据质量门槛。
