# A-Quant 个人策略学习与迭代方案

日期：2026年11月11日。当前软件版本：0.3.1。本文是后续开发方案，所列学习、训练和自动评估功能尚未实现。

用户已确认的首要目标：**优先控制回撤，同时争取收益。** 具体回撤预算、持有周期、交易频率和可接受成本尚未确定，须在正式策略比较前冻结；不根据当前持仓倒推这些偏好。

## 目标与当前差距

长期形态是能够持续记录、复盘、比较和改进的个人研究助手。市场数据提供收益与风险证据，真实操作提供行为反馈，量化模型提出候选方案，组合风控限制风险，DeepSeek综合解释，用户决定实际操作。模型更新必须有可复现的评估记录，并能退回旧版本。

“最佳策略”限定为在约定投资范围、风险约束和评估期间内表现更稳健的候选方案。历史最优不能保证未来最优。反复试验大量参数容易产生看起来优秀的回测，因此必须记录试验次数、保留独立检验和前瞻观察。[回测过拟合研究，Bailey等](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

本次只读检查发现：桌面持仓库有6个标的、6条持仓变更记录，录入日期分布在2天；日报数据目录目前有1个标的的日线缓存。这些是持仓快照和已下载行情，不等于6笔真实成交，也不是足以证明个性化深度模型有效的数据集。后续自动任务可能继续增加缓存，本段仅记录检查时的状态。

代码中已有独立的账户和成交原型（aquant/store.py），但菜单栏日报使用的是另一套持仓快照（aquant/positions.py）。aquant/backtest.py目前是最小快照事件回放；完整历史回测、模型训练、个人操作归因和收益准入仍需建设。

## 学习流程与分工

真实成交、现金流和持仓对账 → 决策当时可见的行情与建议归档 → 周度复盘 → 离线候选模型训练 → 时间顺序验证与组合回测 → 前瞻模拟对照 → 达标版本用于日报 → 新的真实反馈。

| 模块 | 负责的判断 | 约束 |
|---|---|---|
| 市场预测 | 根据市场样本估计未来收益、下行风险或排序分数 | 使用当时可得数据；输出不确定性，不能把评分直接叫作胜率 |
| 个人复盘 | 持有时间、仓位集中、交易成本、操作与建议的差异 | 真实操作是研究材料，不自动当作正确答案；用户明确偏好优先于推断 |
| 组合风控 | 现金、可卖数量、仓位和风险预算，允许的候选动作 | 数据或账户无法核实时不产生具体数量建议；回撤预算不是保本保证 |
| DeepSeek | 结合量化证据综合研判、解释分歧及复盘结果 | 不自行编造收益概率或突破风险限制；输出仍经过最终规则检查 |
| 模型管理 | 保存训练、评估、版本比较和回退记录 | 候选模型通过预先确定的门槛后才可替换当前版本 |

个人持仓、成本和成交细节默认本地处理。提供给DeepSeek的字段沿用明确的数据契约；新增个人信息外发不作为训练功能的隐含条件。

## 第一阶段：建立可信的交易记录和复盘

用户操作入口增加“记录买入”“记录卖出”“导入券商成交”“资金与分红”“查看复盘”。现有“修改持仓”仍表示快照或对账修正，不能把修改数量自动记成一笔成交。

每笔成交至少记录：唯一成交编号、证券代码与市场、股票/ETF类型、买卖方向、实际成交时间、录入时间、数量、原始成交单价、成交金额、费用及数据来源。支持分笔成交、重复导入去重、纠错记录及部分成交。成交原因和关联报告可选；没有对应建议的自主交易也应保留。

账户还需记录期初持仓、现金、资金转入转出、分红和其他证券数量变化。收益和回撤用剔除外部资金流影响的账户净值计算，避免把充值当成盈利、把转出当成亏损。

每个决策时点记录“建议是什么、有没有看到建议、实际如何操作、是否未操作或未知”。只有用户确认未操作才能标记为未执行；没有回执不能自动视为接受或拒绝建议。

每周复盘展示账户净值与回撤、收益来源、费用和换手、持有周期，以及与冻结基线的差异。对“如果没有进行这次交易”的比较必须标明是受成交假设限制的模拟，不能作为因果结论；盈利交易也可能承担过高风险。

实现要点：

- 成交事件账本作为事实来源，持仓是可重建视图；旧快照作为已知日期的起始状态，不虚构此前买卖历史。
- 导入先预览、核对，再提交；按券商成交编号去重。更正保留原始记录与更正关系，支持备份恢复。
- 采用Decimal及实际结算金额核对现金。现有账户原型先把单价换算为分再乘数量，接入ETF成交前必须修正价格精度；费用和可卖规则按证券类型及有效日期处理。
- 历史成交可通过券商导出文件补齐；历史缺失则从已确认的期初状态开始，不推测买入时间和手续费。
- 验收覆盖重复导入、部分成交、精确金额、分红/拆分、资金流、持仓与现金对账、撤销更正和完整恢复。

## 第二阶段：保存可复现的数据，完成回测

当前日线缓存会被更新，不能单独承担“当时知道什么”的审计。新增按日期和内容哈希保存的不可变数据快照、决策快照和数据质量记录。

| 记录 | 需要保存的信息 |
|---|---|
| 行情与特征 | 证券类型、数据源、交易时间、获取时间、原始价格与成交量、复权方式/因子版本、特征版本、质量标记 |
| 建议 | 报告ID、实际生成时刻、输入快照引用、规则和模型版本、原始综合结果、风控后结果、有效期限 |
| 操作反馈 | 实际成交引用、建议关联、反馈时刻、执行/未执行/部分执行/未知、可选原因 |
| 训练样本 | 特征可用时刻、标签开始和结束时刻、标签成熟时刻、样本排除原因、数据版本 |
| 模型实验 | 数据范围、训练与验证窗口、参数、随机种子、代码版本、全部试验结果及淘汰理由 |

缺失数据、失败任务和没有交易的观察日同样保留，避免只留下成功邮件或盈利交易。市场模型需要更广的、按历史时点定义的证券样本；仅研究目前持有的6只标的容易引入选择偏差。ETF与股票分别处理特征、费用、公司行动和交易约束。

回测使用下一可成交时点及明确的成交条件，计入手续费、价差、滑点、停牌、涨跌停、数量限制和流动性。缺失公司行动、历史退市/清盘样本或历史成分信息时，报告其影响范围，不宣称完成无偏验证。

已完成日线可用于日频研究。若要评估用户某次盘中操作的时机，必须有该时点可得的报价；当前14:00日报使用此前已完成日线，不能用当日收盘价冒充14:00已知价格。历史复权数据需保存版本或按当时可用因子重建，避免后来修订的数据泄漏进历史决策。

验收要求：同一数据和版本可重现结果；入账后能重建账户；不得使用未来信息或同一根K线同时产生信号和假定成交；训练标签未成熟时不进入训练。

## 第三阶段：先建立可比较的预测基线

先实现透明规则、线性方法和LightGBM等树模型的对照。收益或下行风险预测与仓位分配分开评价；个人操作数据先用于复盘和约束调整，不直接训练“照着用户过去买卖”的分类器。

研究框架可参考Qlib的数据、模型和实验组织方式，保留独立适配层。其官方基准同时列出树模型、TCN、LSTM和Transformer等模型，比较结果依赖数据集和完整工作流，不能直接移作本账户的收益预期。[Qlib官方基准](https://github.com/microsoft/qlib/blob/main/examples/benchmarks/README.md)

对照组至少包括适当的持有基线、规则策略、机器学习加风控策略及其DeepSeek综合版本；比较时统一股票池、资金流、风险约束和成交假设。DeepSeek的历史知识可能污染历史实验，评价其增益主要依赖从现在开始归档的输入输出和前瞻对照。

## 第四阶段：加入专门的深度学习候选

先考虑TCN或较小的LSTM/GRU时序模型，研究是否改善下行风险估计和信号稳定性。Transformer等更复杂模型在数据覆盖、计算预算和对照证据支持时再加入。模型名称是候选路线，不预先认定某一种最好。

训练主体是足够广的市场历史样本；个人实际交易用于研究行为差异和个性化约束。是否加入个性化学习层，依据独立决策样本量、市场阶段覆盖和学习曲线判断，不以“收集了几个月”自动判定足够。

强化学习暂列远期研究：少量个人交易记录缺少其他动作会产生什么结果的可靠信息，现有成交模拟也不足以支持策略自动试错。应先完成可信模拟和监督学习对照，再评估其必要性。

训练在独立进程中进行，设置资源限制、暂停和恢复能力；菜单栏交互与14:00日报优先。新增一笔交易不触发立即重训，训练须等待相关结果成熟并满足新的评估条件。

## 第五阶段：按回撤优先的标准晋级和迭代

1. 先冻结投资范围、持有周期、回撤预算、成本和评价标准。
2. 按时间顺序划分训练、验证和最终测试。处理相邻标签重叠，隔离跨窗口信息；预处理只在训练集拟合。
3. 记录所有候选与参数试验，避免反复挑选同一测试集的最佳结果。最终测试集使用后不能继续声称它未参与选择。
4. 优先审查组合最大回撤、下行尾部风险及超限情形，再比较扣除成本后的收益、稳定性和换手。也与现金/低换手方案比较，避免单纯追求低回撤而忽略收益目标。
5. 分市场阶段和成本情景检查，展示不确定性；样本不足则保留为研究候选。
6. 候选模型与当前版本并行模拟，所有信号事先保存、事后统一评估；仅统计回测提升不足以晋级。
7. 晋级记录数据、规则、模型和评价版本；持续监测数据异常、预测失准和风险变化。恶化时暂停新增风险建议或回退已验证版本。

具体阈值尚未由用户设定，因此本阶段没有可以直接运行的“最佳策略”选择器。人工下单方式继续由用户决定，自动学习不等于授权程序替用户交易。

## 建议开发顺序

| 规划阶段 | 用户可见交付 | 进入下一阶段的条件 |
|---|---|---|
| v0.4 交易记录与复盘 | 成交表单、导入预览、资金与持仓对账、周度复盘 | 真实账户可核对，金额精确，可恢复与追溯 |
| v0.5 数据与回测 | 决策快照归档、历史数据质量面板、统一基线比较 | 时点一致、成本和交易约束明确、结果可复现 |
| v0.6 机器学习研究 | 规则与树模型对照、回撤与收益报告 | 独立验证和前瞻样本支持候选增益 |
| v0.7 深度学习比较 | 小型时序模型及个性化研究 | 相比简单模型的改进稳定且符合风险目标 |
| v1.0 持续迭代助手 | 版本比较、前瞻观察、晋级/回退、解释与复盘闭环 | 长期运行、研究有效性与数据质量分别验收 |

上述版本是阶段名称，不是交付日期或收益承诺。当前下一项开发应从v0.4的真实成交账本和录入界面开始；回撤容忍值及持有周期在正式策略比较前再确定。
