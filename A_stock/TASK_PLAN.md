## 产品目标和交付范围

开发个人使用的轻量 Python 程序：覆盖沪深北股票信息、已有持仓和自选股；通过量化算法形成证据，再由 DeepSeek 综合研判，经过仓位计算和风控审核，每个交易日北京时间 09:40 和 14:20 生成简短邮件。用户手动录入现金、持仓、交易权限和成交，人工决定是否执行。

采用模块化单体和 SQLite；初期通过命令行及本地轻量面板操作。DeepSeek 是综合决策环节，不能仅作为文字润色器；其推荐需要与量化基线进行独立效果比较。V1 不连接券商下单，不让模型自行更改风控、代码或线上策略。

首个交付是可离线运行的演示闭环，随后完成真实历史研究、受控盘中模拟及自动通知。全市场覆盖是最终目标；每次报告标注实际覆盖率，未获取完整数据时不得宣称已扫描全部 A 股。

## 对原方案的补充和调整

1. 在量化分析与仓位决策之间加入 DeepSeek：读取算法信号、风险指标、可核实资讯和必要的账户约束，输出方向、候选优先级、证据及不确定性。
2. 将交易规则、账户记账和基本回放验证提前到模型之前，避免先生成无法执行的数量。
3. 成交后及时录入反馈；15:10 后用于复核，不能成为上午成交的唯一录入时点。
4. 下午重新计算前确认上午执行情况。未确认时暂停依赖该账户的新增数量建议，可继续发送市场研究与持仓待确认提示。
5. 基础规则演示不依赖 DeepSeek；启用综合模式后，API 故障须明确降级为研究报告，不冒充已完成综合研判。后续可单独审批启用已验证的规则决策模式。
6. 盘后数据按供应商就绪状态更新；不假定 15:10 一定获得完整日线、公告和财务信息。

## 每次运行的业务流程

交易日及运行窗口确认 → 账户版本确认 → 数据采集与校验 → 候选池筛选 → 多策略分析 → DeepSeek 综合研判 → 目标仓位及股数计算 → 全组合风控 → 存档并生成报告 → 邮件投递及状态记录 → 用户成交反馈 → 后续效果评估。

持仓始终纳入监控；被排除的新开仓股票不能从持仓报告中消失。有效但无交易必要输出 HOLD；数据、账户、规则或核心模型异常输出 PAUSED，并说明原因。无效单股可以单独暂停，但若其缺失价格导致组合资产无法可靠估值，则暂停整个账户的数量建议。

## DeepSeek 的职责与边界

输入包括各算法的独立结果、历史有效性、市场状态、风险指标、带来源和时间的新闻摘要，以及账户约束。首版默认不发送姓名、账号和完整资产明细，仓位以比例或约束摘要表达；具体股数在本地计算。后续联调前明确实际提交的字段，密钥不进入报告或日志。

输出使用结构化格式，包含股票、方向、候选顺序、引用的证据编号、分歧处理、风险因素和不确定性。模型自述信心只用于展示，不能当成经过校准的上涨概率。模型可否决买入、建议减仓或观望，但不能突破硬性限制，也不能抵消规则触发的风险退出要求。

只允许推荐证据包中的股票，拒绝未知代码、缺失引用、非法方向和格式错误；新闻、公告中的指令作为不可信文本处理。重试有限次，仍失败则进入暂停状态。API 请求记录模型标识、参数、提示模板版本、输入摘要哈希和完整响应，历史验证使用冻结响应回放；线上重新调用不承诺逐字复现。

算法和模型的意见分歧可形成观望。不得仅因模型解释流畅而提升推荐优先级。最终报告说明哪些建议被风控修改或拦截。

## 必须覆盖的验证场景

| 场景 | 预期行为 |
|---|---|
| 上午买入后下午拟卖出 | 新买部分不计入当日可卖；原有可卖数量按实际成交扣减 |
| 上午建议买300股，实际只买200股 | 只按已录入200股更新；下午基于新快照计算差额 |
| 上午建议执行情况未知 | 暂停账户数量建议，要求确认；不默认执行或未执行 |
| 卖单尚未成交，同时出现买入机会 | 不把预计卖出所得用于买入现金；需要卖出融资的方案只列为条件方案 |
| 多个候选同属一个行业 | 按整批建议的合计敞口检查，不能逐单各自通过后合并超限 |
| 已有持仓超限但停牌或T+1锁定 | 保留风险提示；禁止以计划减仓为由提前增加其他风险 |
| 同一任务运行两次、邮件超时 | 决策和账本幂等；邮件区分待发、已被SMTP接受、结果未知和失败，不承诺严格仅投递一次 |
| 报价过期、时间戳在未来、规则未知 | 拦截受影响的执行建议，记录具体原因 |
| DeepSeek 编造股票、引用不存在的新闻 | 校验失败，有限重试后暂停综合建议 |
| DeepSeek 建议突破仓位或忽略强制风险退出 | 硬风控覆盖，记录原始意见和最终结果 |
| 财报后续修订、历史股票退市 | 使用当时可得版本；无法还原时披露限制，不声称无偏回测 |
| 历史新闻用今天的LLM回测 | 不视为完全无泄漏证据；历史知识可能进入模型，主要以冻结证据和前瞻模拟评价增益 |
| 涨跌停、停牌、跳空或无成交量 | 回测不强制撮合；盘中报告区分建议和可成交性 |

## 数量与账户计算约定

净资产由同一时点的现金、持仓市值和明确的其他资产项核算；手动填写总资产作为对账值，差异超过阈值需确认。区分可用现金、冻结资金和可取资金，避免重复扣除冻结金额。

目标仓位综合市场总仓位、单股行业限制、ATR风险预算和已有不可交易敞口计算；买入差额向下按板块规则修正，不能为了凑最小交易数量向上突破上限。手续费和保守成交价格计入现金预算。卖出不超过实际可卖数量，并按相应零股规则校验。总股票仓位85%、单股10%、行业25%及单笔风险0.5%—0.75%保留为待检验参数；8—12只作为研究目标，不强迫小账户或无机会时凑足数量。

每份数量建议绑定账户版本、数据快照、生成时刻、失效时刻和价格条件。新快照或新报告使旧方案失效，用户仍需检查券商未撤委托；程序不能假定邮件更新就等于旧委托已撤。

## 策略和系统的验收分开

工程验收要求关键记账和风控用例全部通过，无未解决的高严重度问题；每条建议能追溯到数据、规则、模型和账户版本，异常恢复不产生错误交易状态。

研究验收在测试前冻结参数和评价口径，比较净收益、最大回撤、换手、成本、无法成交率及基准超额收益，预测模型另评估Rank IC。使用时间顺序的训练、验证和独立测试，报告不同市场阶段和参数敏感性。不得依据测试集反复调参后仍称独立测试。

DeepSeek 的增益同时考察风险、换手、成本、输出稳定性、API成本和时延；相同输入允许存在输出差异，需要固定模型及模板版本并做稳定性抽样。没有可靠增益时保留为研究模式，不自动投入实盘辅助。

前瞻模拟建议先观察2—3个月，若行情单一、样本不足或存在明显执行偏差则延长。运行时间本身不构成策略通过。实盘辅助的最大可接受回撤、通知成功率、行情时效、覆盖率和预算上限需在模拟前明确冻结；本规划不虚构统一盈利门槛。
