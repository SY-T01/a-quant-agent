# 行业与公司综合研究使用指南

系统现在以3—6个月为目标持有周期，增加独立的行业优先研究工作台。原有短周期演示选股程序保留，但它的分数和回测不能作为中期系统已验证的结果。

## 直接使用

在 Finder 中进入 `/Volumes/tsy_macmini/work/stock/stock_selecter/`：

1. 双击 `启动综合研究.command`：更新公开行业资金流并在默认浏览器打开研究页。网络失败时保留上一次完整行业快照，报告明确显示更新失败与数据时间。
2. 不联网也可直接双击 `reports/sector_research/index.html` 查看已经生成的页面。
3. 在页面搜索框输入行业名称或板块代码，查看当日、5日和10日主力净额，单位为亿元。
4. 公司观察池列出资金关注板块中的当前成份样本；没有真实财务资料时，正式公司研究候选保持为空。

```sh

```

## 行业榜该怎么看

资金关注分是当日、5日、10日主力净额占比的横截面分位数，权重15%、35%、50%。这是为了展示短期资金偏好设置的起始假设，不是经过验证的3—6个月收益预测。净流入/流出是供应商按成交分类计算的代理指标，不等于基金或机构真实持仓变化。

目前接口返回496个多层级行业板块，父子行业可能重叠；不能把所有净额加总。当前全板块排名也未完成层级中性处理，不宜拿一级行业与细分三级行业直接作投资优劣比较。下一轮需要核对统一一级行业分类及成份映射。

对中期投资，更有意义的证据链是：

- 资金：20/60/120交易日持续性、行业内上涨和净流入广度、是否只有少数龙头贡献。
- 产业：需求、产能、价格、库存、订单和政策催化，注明数据与公告日期。
- 盈利：行业利润和收入变化、盈利预期是否上修、利润兑现程度。
- 估值：行业历史分位、盈利变化与估值扩张的关系，避免仅因为上涨而追高。
- 市场与风险：63/126交易日相对基准收益、回撤、拥挤度、行业周期与逻辑失效条件。

这些证据尚未全部接入时，页面明确标记“证据不足，仅作资金观察”，不会把关注分换算成上涨概率。

## 公司观察池与公司候选

公司观察池自动取资金关注榜中5日/10日均净流入的前5个板块，每个板块按当日主力净额取最多20只当前成份。它不是完整同业全集，存在重复公司、板块重叠与短期选择偏差，当前成份也不能回填历史。

动态PE与PB只作供应商快照展示，不假定它们为已审计TTM值；缺失或负值不美化处理。正式公司候选另需财务与历史估值证据。

可将 `data/research/companies_template.csv` 复制为 `data/research/companies.csv`，导入经核对的真实公司数据。字段说明：

|字段|约定|
|---|---|
|symbol、name、industry_code|证券代码、公司名、本报告板块代码|
|disclosed_at|本行全部资料最晚披露/可见时刻，必须带时区，如2026-10-30T20:00:00+08:00|
|source_url|可核验的数据或公告来源；如合并多份数据需上游保留各项来源|
|revenue_growth_yoy、profit_growth_yoy|同比增长率，小数，如0.10代表10%|
|roe_ttm|TTM ROE，小数|
|operating_cashflow_to_profit|经营现金流/净利润|
|pe_ttm|TTM PE，亏损不视作低估值|
|pe_history_percentile|本公司历史PE分位，0—1；需在上游统一历史窗口|
|debt_ratio|资产负债率，0—1|
|return_60d|60交易日收益，小数；必须统一复权口径|
|is_st、audit_ok|0或1，未知不能假定通过|

系统排除尚未披露、过旧、关键字段缺失、ST/审计未通过、负利润与部分现金流/增长条件不通过的记录。通过后按同一板块内部比较盈利增长25%、ROE25%、现金流质量20%、低估值分位20%、60日趋势10%。这些条件和权重尚未经过样本外验证。银行、保险、工业、周期股需要专属质量指标；通用评分只能帮助整理研究，不能代替人工尽调。同业样本只有一家时分位为中性，不能解释为比较优势。

运行本地资料更新：

```sh
python3 -m stock_selector.sector_research
```

## DeepSeek接入

双击 `启动DeepSeek解读.command`，在本地终端输入密钥，输入不会显示，也不会保存在文件中。脚本将已有研究报告中的公开行业/公司证据发送到DeepSeek；不会发送整个项目或原始数据目录。调用会消耗你的API额度。首次使用前先运行综合研究，以便生成行业缓存。

也可在已有环境变量 `DEEPSEEK_API_KEY` 的终端运行：

```sh
python3 -m stock_selector.sector_research --ai
```

默认模型 `deepseek-flash`，可通过 `DEEPSEEK_MODEL` 环境变量指定账号可用模型。采用官方 `https://api.deepseek.com/chat/completions` 和JSON输出。最多发送前15个行业、前20家公司候选和前20个公司观察样本，不代表对全部板块做完整AI覆盖；显式关闭思考模式，限制单次输出4096 tokens，不做自动重试计费。

DeepSeek只整理证据、指出缺口、给出研究假说；它不获取实时行情，不自主联网查公告，不补造盈利预测，不改动计算分数。程序校验其引用ID是否存在，但无法证明每句文字解释正确；报告保留人工核实提示、模型名、用量和输入校验值。缺少密钥、接口失败、JSON结构或引用校验失败时仍生成本地数据报告，明确说明AI未完成。

官方调用参考：https://api-docs.deepseek.com/quick_start

### 网络超时与分段响应

DeepSeek调用现采用官方SSE流式响应，在服务连接成功后会显示“正在分段接收解读”，接收期间定期显示进度。单次网络读取等待上限120秒，接收循环检查300秒总耗时；不自动重复请求。仅在收到完整结束标志且JSON和证据校验通过后采纳结果，中途断线不采纳部分结论。服务如返回普通JSON也支持读取。

## 条件买入候选

报告新增“建议优先考虑的股票”，最多5只、每行业最多2只，由已取得的行业资金与真实季报计算，再核验腾讯行情。筛选要求行业5日和10日均净流入，公司盈利且收入利润增长，累计营收至少10亿元、归母利润至少1亿元、现金流/归母净利润0.8至5，供应商行情PE为正且不超过45、PB不超过6、最近有效行情成交额至少2000万元。以上均为未作收益优化的初始研究门槛；不适用于缺少可比现金流的金融股。

行业快照超过7个自然日、股票行情超过5个自然日或财报报告期超过180日时不入选；缺少估值不补零，名称含ST或退市标记、财报和行情名称不一致时排除。名称过滤和最近有成交不能代替完整交易状态检查，买入前仍需复核。候选行情参考价不是委托价或未来保证成交价。PE字段只按供应商快照展示，尚未交叉核验为TTM。

每只股票展示三条可计算入选理由、买入前提、逻辑失效/重新评估条件及周期和高增长低基数风险。不虚构目标价，不按预测收益分配仓位。DS只能解释规则已选出的名单，不自行新增股票。用户风险承受能力和已有持仓尚未纳入，因此为一般条件研究建议。

每周一现有流程更新数据时也会更新该名单，周报归档记录新入选、移出和完整买入前提。没有合格股票时允许空名单。行情原始数据保存在data/raw/tencent/recommendation_quotes/，清洗缓存保存在data/normalized/sector_research/recommendation_quotes.json，仍使用外置磁盘。

## 两级决策 初筛提案与大模型反向复核

现在股票流程分成两个角色：

1. 小模型阶段是当前透明规则评分器M0，尚未训练成收益预测模型。它从行业、季报、现金流、估值中找出候选，给出分项得分与理由，输出的是提案。
2. 大模型阶段是DeepSeek。它不只总结提案，而要逐股审查反面理由、证据缺口，并给出“有条件通过/暂缓/否决”。可以全数否决。关键阻断项未解决时不能标为通过。
3. 最终名单只含本期已通过复核的股票。未调用、调用失败、漏审、乱加股票、引用不匹配或证据已变化时都不算通过。当前没有大模型凭据时，报告保留初筛候选，但最终买入名单为空并标记待复核。

应用菜单中的“大模型逐股复核与买入计划”执行一次调用。股票最多5只时输出上限调整为8192 tokens，关闭思考模式，保留流式接收和诊断，不自动付费重试。

每只通过复核的股票必须列出开始条件、1至4批计划、取消条件及退出复核条件。比例合计100%，只指用户另行确定的该股计划金额，不是用户全部资产。暂缓或否决股票不展示买入分批。没有可靠定价依据时不编造目标价、波动止损线或保证收益。

周报HTML和Markdown并列展示：量化初筛理由及分数、大模型意见、反方论据、分歧、最终处理、如何分批与何时不买。周更新归档同时保存四种复核状态的数量。大模型只对所提供材料做逻辑和证据审查，当前不自主联网查公告；事实独立核实仍需可靠数据源或人工完成。

每周一实时更新会在运行环境已配置DEEPSEEK_API_KEY时执行一次复核；只运行缓存验证时即便有密钥也不调用AI。之前手工输入的密钥不会永久保存，因此没有为定时环境配置凭据时，周报会明确显示待复核，不会虚构大模型已同意。

复核与初筛价格、财报、行业证据绑定。证据变化后旧复核失效；只有证据完全一致才复用上次有效意见。程序校验模型结构、代码、覆盖、引用、比例和阻断项，不保证模型文字推理正确。报告与数据继续保存在当前外置磁盘项目目录。

## 逐股复核容错与不收费重放

现在大模型完整返回后，逐只处理结果，不再因一只股票的计划字段不完整而丢弃整批意见。暂缓、否决无需提供买入计划；通过但计划缺少必要项的显示“已复核，计划待补全”，保留理由和反方观点，但不进入最终买入名单；引用、重复或结构有问题的显示“已返回，需核实”。只有本次模型确实没有覆盖的股票才显示待复核。

程序支持entry_trigger/exit_condition等少量明确的字段别名，但不推测目标价，不为模型补造分批条件。仍有关键阻断项或不合法分批比例的股票不能通过操作计划检查。每股程序校验问题单独展示，其他股票的有效通过、暂缓、否决不受影响。

新的完整JSON返回会在校验前保存到 `reports/ai_responses/`，只含模型正文、用量和证据绑定信息，不含密钥或HTTP认证头。以后修正解析逻辑时，可在统一菜单选择“重新处理已保存的AI结果（不收费）”，不再调用API。存档必须与本期价格、财报及初筛证据一致，否则不用于当前判断。

旧版在格式校验失败时未保存正文，因此不能从只有错误提示的旧报告恢复那次付费结果。新增留档只对修改后的调用生效。

## 分享版PDF

报告每次生成后会自动导出 `reports/sector_research/行业研究周报.pdf`。网页顶部可点击“下载分享版PDF”，或在助手菜单选择“导出分享版PDF”，单独从当前已保存的研究JSON排版，不重新抓取行情，也不调用DeepSeek。

分享版包含本期行业资金、量化初筛、大模型逐股复核、适用的买入分批/暂缓条件、公司财务线索、来源时间与使用边界。全文使用嵌入式中文字体，带页码，接收者无需安装本项目即可阅读。不导出API密钥、技术日志或本机文件路径。暂缓或待复核股票不会在PDF中变成已通过买入名单。

每周自动更新和归档也会附带该PDF。排版使用本机已配置的Codex文档运行环境与系统中文字体，路径记录在configs/pdf.json；运行环境不可用时会明确提示，HTML报告仍然保留。PDF采用临时文件完整生成后替换，导出失败不会覆盖旧PDF。

## 宏观与公司前景

新一轮更新已接入统计局与央行7项宏观指标、候选公司业务资料及原始公告。网页、文字周报和PDF均新增“宏观分析与公司发展研究”。来源日期、业务事实、管理层表述、模型推断和条件情景分别标注。详见同目录“宏观与公司发展研究迭代.md”。

新增资料会使原有复核不再适用。现在可以在应用中运行一次“大模型逐股复核与买入计划”，它将用新增资料重新审查，并返回定制的三种公司发展情景。尚未运行前，报告中的情景明确为本地条件研究框架，不表示大模型已经同意买入。
